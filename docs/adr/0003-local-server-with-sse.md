# 棋盘与会话之间走本地常驻服务，SSE 下行 + POST 上行

**Status: superseded by ADR-0004** —— 用户要求做进 DSH 侧边栏而不是另开一个网站，于是放弃了自建服务，改做 DSH 插件。保留在这里是因为「为什么不要 `file://` 变通」与「为什么不用 WebSocket」这两条论证依然成立。

硬需求是**双向**：人能在棋盘上操作，会话也能随时读盘、落子、支招。此前为了保住「双击即开的纯 HTML」把上行通道砍成只读，是用硬需求换软偏好，取舍反了。现在定为：`xq serve` 起一个零依赖的本地 Node 服务，它是棋局的唯一权威；网页由这个服务提供，走 **SSE 下行 + POST 上行**；`xq` 的其余命令都只是这个服务的客户端。

## Considered Options

- **坚持 `file://`，上行靠变通**（下载目录监听、自定义协议、剪贴板中转）：全部依赖浏览器策略与用户设置，脆且难查，且仍然要额外起一个接收进程——已经付出服务的代价，却没得到服务的可靠性。否决。
- **WebSocket**：语义更顺，但 Node 没有内置 WS 服务端，要么手写握手与帧解析，要么引入依赖。SSE + POST 用纯 `node:http` 就能覆盖本场景的全部需求（服务端广播 + 客户端提交），所以不必要。否决。
- **页面轮询 `/state` + POST**：能work且更笨，但轮询延迟与无谓请求都不如 SSE。作为 SSE 连不上时的兜底保留。

## Consequences

- 人不再双击 HTML，而是打开 `http://127.0.0.1:端口`。服务没起时棋盘不可用——这是这个决定的直接代价,接受。
- 服务未启动时，直接双击 `chinese-chess-board.html` 仍应退回纯本地自由摆棋模式。这条降级路径几乎免费，保留它，但它不再是主线。
- 会话不需要轮询：用一条阻塞命令挂成后台任务，人一落子该任务就结束，会话随即被唤醒接招。人不必打字。
- 端口不能写死，服务把实际端口与 pid 写进一个发现文件，CLI 命令据此找到它。
