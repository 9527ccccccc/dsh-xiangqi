# 棋盘做成 DSH 插件，不再自建本地服务

用户的硬需求是「做进 DSH 侧边栏，不要我多开一个网站」。DSH 本来就带 Web GUI、插件体系和一个可扩展的侧边栏，自建服务则要另起常驻进程、另开页面、还得自己做认证与生命周期——为了一个已经存在的东西付两份成本。所以棋盘做成插件：**host 半边**（`lib/index.js`）持有棋局并注册会话可调用的工具，**client 半边**（`lib/client.js`）把棋盘画进 GUI 的右栏，两边走 DSH 自己的 RPC 通道。

## Considered Options

- **自建本地服务 + 独立网页**（ADR-0003）：能work，但用户明确不要第二个网站；且进程生命周期、端口、认证都要自己兜。否决。
- **MCP server**：能给我工具，但给不了人一块能点的棋盘。否决。
- **skill + CLI**：最省事，但没有面板，人还是得在对话里打字下棋。作为没有 GUI 时的降级保留。

## Consequences

- 棋盘的 UI 只能落在 DSH 已经声明过的插槽里（右栏是 `sidebar.right.pane.tab`）。GUI 的布局由宿主说了算，插件不能自己造一块地方。
- host ↔ client 的通路受 DSH 限制：可用的服务名、事件类型都有白名单，插件加不了自己的 WebSocket 消息类型。
- 棋局状态的生命周期跟着 DSH 进程走，落盘才有跨重启的持久化。
- 插件写错了会**大声失败**（缺 `lib/client.js` 会激活报错），所以开发期要有回滚路径：插件挂在 profile 的 `cordis.patch.yml` 上，摘掉即可。
