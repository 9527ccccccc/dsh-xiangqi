# 会话能双向通讯的象棋棋盘与 CLI

> **Status: superseded by [ADR-0004](../adr/0004-chess-as-dsh-plugin.md).** 这份规格要求自建一个
> 本地常驻服务 + 独立网页。用户随后明确「不要我多开一个网站」，于是改成做 DSH 插件。
> 保留在这里是因为其中的双向通道设计、`xq` 命令面与失败模式分析仍然有参考价值。

`ready-for-agent`

## Problem Statement

现在这个棋盘是个孤岛：所有操作都要人用手摆，会话（DSH 里的 AI）看不见盘面、也碰不到棋子。人和会话下一盘棋，人得当搬运工——把局面念给会话听，再把会话的着法摆到页面上去。两边明明在同一台机器上，却只能靠人嘴传话。

## Solution

给这个仓库加一个**本地常驻服务**，它持有棋局的唯一真相，并同时伺候两个客户端：

- **网页**由这个服务提供，与服务实时双向：人点两下就能落子，非法着法当场被拒并说明原因；会话落的子、给的支招、将军与胜负提示，页面不刷新就出现。
- **`xq` 命令**是同一个服务的客户端。会话用 `xq board` 看清局面，用 `xq move 炮二平五` 落子，用 `xq hint` 把建议着法送到页面上。
- **对局**模式下强制标准象棋规则：非法着法走不动，被将军必须应将，将死或困毙判负。
- **摆棋**模式原样保留：随意摆放任意棋子到任意交叉点，页面和命令都能摆。
- 会话用一条阻塞命令挂成后台任务，人一落子就唤醒会话接招——**人不需要打字**，真正像在跟一个对手下棋。
- 服务没起时，直接双击 HTML 仍是今天这个纯本地自由摆棋器。

## User Stories

1. 作为对局者，我想直接对会话说「开局」，让它重置棋盘并等我走第一步，这样我不用手动摆 32 枚棋子。
2. 作为对局者，我想在棋盘上点两下就落子，不用打字、不用背记谱法。
3. 作为对局者，我想在轮到我走时被明确告知，这样我不会替对方走子。
4. 作为对局者，我想在页面上落子后，**会话自动接招**，我不用再打字催它。
5. 作为对局者，我想在页面上看到会话刚落的子，不刷新页面，这样我能一直盯着棋盘下完一整局。
6. 作为对局者，我想让非法着法当场被拒绝并告诉我原因（马腿被蹩、象眼被塞、不能自杀、必须应将），这样我不会以为自己走成了。
7. 作为对局者，我想在选子时看到这枚子所有能走的位置，这样我不用试错。
8. 作为对局者，我想在被将军时立刻看到提示，这样我不会漏应。
9. 作为对局者，我想在被将死或困毙时看到结果和原因，这样我知道这一局结束了。
10. 作为对局者，我想在走之前让会话给我支招，并让那一步在棋盘上用箭头高亮，这样我既能看见也能听见理由。
11. 作为对局者，我想让支招随时能撤，这样它不会挡着我的眼睛下完整局。
12. 作为对局者，我想悔棋一次退一整轮（我一步、会话一步），回到该我走的状态。
13. 作为对局者，我想看到已经走过的着法列表，这样我能回看这一局怎么走到这里的。
14. 作为对局者，我想让棋局留在磁盘上，关掉浏览器再打开，棋还在原处。
15. 作为对局者，我想用中文记谱说话（「炮二平五」）也能走子，这样我用的是象棋本来的语言。
16. 作为对局者，我想在页面上直接输入中文记谱走子，这样两种方式随我挑。
17. 作为对局者，我想在摆棋模式里把任意棋子放到任意交叉点，页面和会话都能做。
18. 作为对局者，我想在摆棋和对局两种模式之间显式切换，这样我不会在认真下棋时手滑改动了局面。
19. 作为对局者，我想让页面在服务没起时仍能自由摆棋，这样我把这个 HTML 单独发给朋友，它还是个能用的摆棋器。
20. 作为对局者，我想在棋盘上看见「谁在跟我下」，这样我不会把两个来源的着法搞混。
21. 作为会话，我想用一条命令读到机器可读的完整局面（含 FEN、轮到谁、合法着法、着法历史），这样我不必解析自然语言。
22. 作为会话，我想用一条命令枚举当前所有合法着法，这样我能系统地找棋而不是凭空猜。
23. 作为会话，我想在落子后立刻收到结构化回执（是否合法、是否将军、是否终局），这样我知道下一步该说什么。
24. 作为会话，我想有一条**阻塞命令**能挂成后台任务，人一落子它就返回并把我唤醒，这样对局能自动流转。
25. 作为会话，我想在不打开浏览器的情况下跑完整局棋（自测时连走几十步），这样规则引擎可被验证。
26. 作为会话，我想让每次失败都有明确的退出码和原因，这样我犯错时被立刻纠正而不是默默摆错。
27. 作为会话，我想能清空棋盘、放一枚子、拿走一枚子，这样我能配合人摆局面。
28. 作为会话，我想在服务没起时得到一句明确的「先跑 xq serve」，而不是一个连不上的报错。
29. 作为维护者，我想让规则引擎与记谱转换是可以单独调用的纯函数，这样我能在不启动服务的情况下测它们。
30. 作为维护者，我想让棋局真相与网页渲染彻底分开，这样换前端不会碰到规则代码。

## Implementation Decisions

### 架构

一个零依赖的本地常驻服务是唯一权威，内存里持有当前棋局，每次变更落盘一份真相文件。网页与 `xq` 命令都是它的客户端，两者走**同一套 HTTP 接口**——网页不该有命令没有的后门，命令也不该有网页没有的特权。取舍与被否决的备选（`file://` 变通、WebSocket、轮询）见 ADR-0003。

- **下行用 SSE**：服务在局面变化时向所有连接的客户端广播。会话落的子、支招、终局，都在同一条广播里。
- **上行用 POST**：客户端提交着法与操作，服务校验后返回结果；非法时返回原因和这枚子的合法着法列表。
- 端口不写死。服务启动后把实际端口与 pid 写进一个发现文件，`xq` 的其余命令据此找到它。
- 真相文件入盘、派生状态不入版本库。

### 命令面

单一入口 `xq`（Node，零依赖）。stdout 给人读，`--json` 给机器读，退出码 0/1。每个命令都是对服务的一次调用；服务没起时明确报错并提示 `xq serve`。

- `xq serve [--port N]` — 起服务，页面在 `http://127.0.0.1:端口`
- `xq new [--mode game|setup] [--first red|black]` — 开新局，默认对局模式、人执红先走
- `xq board` — 打印局面：文本棋盘、该谁走、是否被将军、着法表、FEN
- `xq move <着法>` — 走一步，接受中文记谱（`炮二平五`）或坐标（`h2-e2`、`7,9-7,7`）
- `xq moves` — 列出该走一方全部合法着法
- `xq legal <col,row>` — 列出某个交叉点上棋子的全部合法着法
- `xq status` — 一行摘要：模式 / 该谁走 / 是否将军 / 结果 / 着数
- `xq undo` — 悔一整轮，回到人该走的状态
- `xq hint <着法>` / `xq hint --clear` — 发布或清除支招
- `xq wait [--timeout S]` — 阻塞到局面发生指定变化（典型用法：等人走完），用于把会话唤醒
- `xq place <红|黑> <子名> <col,row>`、`xq remove <col,row>`、`xq clear`、`xq mode <game|setup>` — 摆棋模式的原子操作

### 规则引擎

实现标准中国象棋：车走直线、马走日但蹩马腿、象走田但塞象眼且不过河、士在九宫斜走、将帅在九宫一步、炮直线走而隔一子吃、兵卒过河前只进过河后可横。**将帅照面（白脸将）判非法**。落子后不得自将；被将军必须应将。

终局判定：**将死判负；困毙（轮到走的一方无任何合法着法）同样判负**——这是中国象棋与西洋棋的关键差异，困毙不是和棋。和棋情形：三次重复局面判和；60 回合无吃子判和。

> 更正：本会话早先把它说成「无着可走判和」，那是错的，以本节为准。

长将判负要求区分「单方连续将军」与「双方互不变着」，实现与测试成本明显高于其余部分，因此**三次重复局面判和先做，长将判负列为增强**。

### 记谱

内部一律用列/行坐标；中文记谱只是面向人和会话的表示层，两者互转必须双向无歧义。红方用汉字数字、从右向左数（一至九），黑方用阿拉伯数字、从左向右数（1 至 9）。同列出现两枚同名子时用「前/后」区分，兵卒出现三枚及以上同列时用「前/中/后」。记住一个反直觉之处：记谱里的「进/退」是相对各方的，红方的「进」是行号变小。

### 网页

在现有单文件上增量改造，不重写。服务在 `GET /` 时把这份 HTML 读出来返回，因此它仍是可单独编辑的单文件。

- 连上 SSE，按广播重绘；同时保留一个低频轮询兜底，防长连接断掉后页面僵死。
- 对局模式界面：轮谁走、被将军、终局横幅、着法表、支招箭头、选中棋子的可走位置。
- 点两下选子选落点即提交；被拒时就地显示原因与合法着法。另给一个中文记谱输入框。
- **降级路径**：连不上服务（脚本报错或发现文件缺失）时，静默退回今天这套本地自由摆棋，不弹错、不白屏。这条必须有测试。

### 模块边界

规则、记谱、棋局状态各自独立成模块，都不依赖浏览器、不依赖 HTTP、不依赖 CLI 的输出格式。服务层只负责把这三样接到协议上；CLI 是一层薄客户端。

## Testing Decisions

三个接缝，都取既有形状里最高的那个：

1. **`xq` 命令 + 它背后的服务（主接缝）**。测试真起服务、真 spawn 命令进程，断言 stdout、退出码与落盘真相。这是会话实际使用的界面，覆盖「开局 → 走子 → 将军 → 将死 → 悔棋 → 支招」整条链路，也顺带锁住命令面契约。绝大多数场景应该在这里测。
2. **规则引擎与记谱的纯函数（次接缝）**。只用来测着法生成的逐子表格：各子力在若干给定局面下的合法着法集合，含蹩马腿、塞象眼、炮翻山、兵过河、将帅照面这些边界；记谱做往返测试。理由是用命令进程逐例跑又慢又吵，而这类表驱动断言正是纯函数最擅长的。
3. **网页（Playwright）**。打开服务提供的页面，点两下走子，断言服务确实收到了着法且页面随之更新；走一步非法棋，断言就地出现原因；由服务推一条支招，断言箭头出现。浏览器测法已有先例——本目录的 `file-protocol-live-control.md` 就是这套跑法。

测试只断言外部行为：命令的输出、落盘的状态、HTTP 的响应、页面上的可见结果。不断言内部函数名、文件布局或消息字段的私有细节。

## Out of Scope

棋钟与计时、多局管理与存档回放、残局库、AI 难度分级、挂 UCI 引擎当对手、联机与观战、手机端专门适配、悔棋到任意一手、长将判负、自写 WebSocket、以及**任何形式的 `file://` 双向变通**（下载目录监听、自定义协议、剪贴板中转）。

## Further Notes

- [file-protocol-live-control.md](file-protocol-live-control.md) 是 ADR-0001 的原始证据（结论重写版）。ADR-0001 已被 ADR-0003 取代，但那些实测结论（默认浏览器里 `file://` 页面能做什么、不能做什么）依然有效。
- `state/` 是运行时目录，不入版本库。
- 这一期最容易被低估的活是中文记谱的双向转换，尤其是同列重子的「前/中/后」；它比规则引擎更容易出现难查的边界错误。
- 端到端的对局循环是：会话挂 `xq wait` 当后台任务 → 人落子 → 任务返回把会话唤醒 → 会话 `xq board` 想棋 → `xq move` → 页面经 SSE 立刻更新 → 会话再挂一次。这个循环是本期真正的验收标准。
