# 会话直接操控的象棋 CLI 与对局

`ready-for-agent`

## Problem Statement

现在这个棋盘是个单文件网页：所有操作都要人用手摆，会话（DSH 里的 AI）看不见盘面、也碰不到棋子。人想和会话下一盘棋，就得自己当搬运工——把局面念给会话听，再把会话的着法摆到页面上。会话明明就在同一个工作目录里跑命令，却对棋盘一无所知。

## Solution

给这个仓库加一个零依赖的 Node CLI `xq`，它持有**局面**的唯一真相，并会说话：

- 会话用 `xq board` 一眼看清局面，用 `xq move 炮二平五` 落子，用 `xq hint` 把建议着法送到页面上。
- 网页变成 CLI 的实时显示端：CLI 一落子，页面不刷新就跟着变；被将军、轮谁走、结果、建议着法箭头都在页面上看得见。
- **对局**模式下强制标准象棋规则：非法着法走不动，被将军必须应将，将死或困毙判负。
- **摆棋**模式原样保留：随意摆放任意棋子到任意交叉点，CLI 也能摆。
- 没有 CLI 的时候（比如把 HTML 单独发给别人），页面自动退回今天这个纯本地自由摆棋器，一个字都不用改。

## User Stories

1. 作为对局者，我想直接对会话说「开局」，让它把棋盘重置成标准开局并等我走第一步，这样我不用手动摆 32 枚棋子。
2. 作为对局者，我想在页面上看到会话刚落下的那一手，而不用刷新页面，这样我能一直盯着棋盘下完一整局。
3. 作为对局者，我想让会话告诉我现在的局面（谁走、是否被将军、还剩哪些子），这样我不用自己数。
4. 作为对局者，我想用中文记谱说话（「炮二平五」）就能走子，这样我用的是象棋本来的语言。
5. 作为对局者，我也想在页面上点两下选子选落点，让页面把这一步写成中文记谱给我复制，这样我不必背记谱法。
6. 作为对局者，我想让非法着法被拒绝并告诉我为什么（马腿被蹩、象眼被塞、不能自杀、必须应将），这样我能学会正确的走法而不是摆出一个假局面。
7. 作为对局者，我想在被将军时立刻看到提示，这样我不会漏应。
8. 作为对局者，我想让被将死或被困毙时立刻看到结果和原因，这样我知道这一局结束了。
9. 作为对局者，我想在走之前让会话给我支招，并让建议的那一步在页面上用箭头高亮，这样我既能看见也能听见理由。
10. 作为对局者，我想悔棋一次退一整轮（我一步、会话一步），回到该我走的状态，这样我走错一步不至于毁掉整局。
11. 作为对局者，我想让会话在轮到我时闭嘴等着，不替我走子，这样棋是我在下。
12. 作为对局者，我想在摆棋模式里把任意棋子放到任意交叉点，CLI 也能做同样的事，这样我能自己设计一个残局丢给会话下。
13. 作为对局者，我想在摆棋和对局两种模式之间显式切换，这样我不会在认真下棋时手滑改动了局面。
14. 作为对局者，我想让页面在没有 CLI 时仍然能自由摆棋，这样我把这个 HTML 单独发给朋友，它还是个能用的摆棋器。
15. 作为对局者，我想让对局文件留在磁盘上，关掉浏览器再打开，棋还在原处。
16. 作为对局者，我想看到已经走过的着法列表，这样我能回看这一局怎么走到这里的。
17. 作为会话，我想用一条命令读到机器可读的完整局面（含 FEN 和合法着法），这样我不必解析人的自然语言。
18. 作为会话，我想用一条命令枚举当前所有合法着法，这样我能系统地找棋而不是凭空猜。
19. 作为会话，我想在落子后立刻收到「这一步是否合法、是否将军、是否终局」的结构化回执，这样我知道下一步该说什么。
20. 作为会话，我想在被人要求支招时把建议着法发布到页面，这样人不用在对话里翻找坐标。
21. 作为会话，我想在一个不依赖浏览器的地方跑完整局棋（比如自测时连走几十步），这样规则引擎可以被验证。
22. 作为会话，我想让 CLI 的每一次失败都有明确的退出码和原因，这样我犯错时能被立刻纠正而不是默默摆错。
23. 作为摆棋的人，我想让 CLI 也能清空棋盘、放一枚子、拿走一枚子，这样会话能配合我摆局面。
24. 作为维护者，我想让规则引擎与记谱转换是可以单独调用的纯函数，这样我能在不启动浏览器的情况下测它们。
25. 作为维护者，我想让派生视图可以随时从真相重建，这样它坏掉了不用担心，重跑一条命令就好。

## Implementation Decisions

### 状态与流向

真相是磁盘上的一个对局文件，CLI 独占读写；网页读的是 CLI 每次变更后重新生成的**派生视图**（一个把同一份数据包成 `window.XQ_STATE = {...}` 的 JS 文件），每 350ms 动态插入一次 `<script src>` 拉取。这条通道是被实测逼出来的，理由与备选方案见 ADR-0001；真相归属见 ADR-0002。

真相文件的结构（骨架，字段含义比字面更重要）：

```json
{
  "mode": "game",
  "turn": "red",
  "pieces": [{ "color": "red", "type": "R", "col": 0, "row": 9 }],
  "history": [{ "notation": "车九平八", "from": [0, 9], "to": [0, 8], "captured": null }],
  "hint": { "from": [1, 7], "to": [4, 7] },
  "result": null
}
```

`result` 非空时形如 `{ "winner": "red", "reason": "将死" }`。`history` 的每一项都足以重放这一局，因此悔棋就是弹栈加重建局面。

**数据只向一个方向流：CLI → 派生视图 → 网页。** `file://` 页面没有任何写盘能力（ADR-0001），所以人的着法不可能从页面回流。人的消息就是回合边界：人不说话，会话不动。页面上的「点两下选子」只在本地产出中文记谱加一个复制按钮，不假装能提交。

### 命令面

单一入口 `xq`（Node，零依赖）。stdout 是给人读的，`--json` 给机器读，退出码 0/1。

- `xq new [--mode game|setup] [--first red|black]` — 开新局，默认对局模式、人执红先走
- `xq board` — 打印局面：文本棋盘、该谁走、是否被将军、着法表、FEN
- `xq move <着法>` — 走一步，接受中文记谱（`炮二平五`）或坐标（`h2-e2`、`7,9-7,7`）
- `xq moves` — 列出该走一方全部合法着法（中文记谱 + 坐标）
- `xq legal <col,row>` — 列出某个交叉点上棋子的全部合法着法；用于「这一步为什么不能走」
- `xq status` — 一行摘要：模式 / 该谁走 / 是否将军 / 结果 / 着数
- `xq undo` — 悔一整轮，回到人该走的状态
- `xq hint <着法>` / `xq hint --clear` — 发布或清除页面上的建议着法箭头
- `xq place <红|黑> <子名> <col,row>`、`xq remove <col,row>`、`xq clear` — 摆棋模式的原子操作
- `xq publish` — 强制重新生成派生视图；派生视图丢失或损坏时的修复命令

### 规则引擎

实现标准中国象棋：车走直线、马走日但蹩马腿、象走田但塞象眼且不过河、士在九宫斜走、将帅在九宫一步、炮直线走而隔一子吃、兵卒过河前只进过河后可横。**将帅照面（白脸将）判非法**。落子后不得自将；被将军必须应将。

终局判定：**将死判负；困毙（轮到走的一方无任何合法着法）同样判负**——这是中国象棋与西洋棋的关键差异，困毙不是和棋。和棋情形：三次重复局面判和；60 回合无吃子判和。

> 更正：本会话早先把它说成「无着可走判和」，那是错的，以本节为准。

长将判负要求区分「单方连续将军」与「双方互不变着」，实现与测试成本明显高于其余部分，因此**三次重复局面判和先做，长将判负列为增强**。

### 记谱

内部一律用列/行坐标；中文记谱只是面向人和会话的表示层，两者互转必须双向无歧义。红方用汉字数字、从右向左数（一至九），黑方用阿拉伯数字、从左向右数（1 至 9）。同列出现两枚同名子时用「前/后」区分，兵卒出现三枚及以上同列时用「前/中/后」。记住一个反直觉之处：记谱里的「进/退」是相对各方的，红方的「进」是行号变小。

### 网页

在现有单文件上增量改造，不重写：

- 轮询并注入派生视图，只在版本号变化时重绘，避免闪烁。
- 对局模式的界面：轮谁走、被将军的提示、结果横幅、着法表、建议着法箭头。
- 点两下选子选落点，页面算出中文记谱并给出复制按钮；不做任何提交尝试。
- **降级路径**：派生视图缺失或脚本加载失败时，静默退回今天这套本地自由摆棋，不弹错、不白屏。这条必须有测试。

### 模块边界

CLI 入口一层薄壳，规则、记谱、状态读写各自独立成模块，互不依赖浏览器，也互不依赖 CLI 的输入输出格式。

## Testing Decisions

两个接缝，都是既有形状里最高的那个，不新增多余的：

1. **CLI 进程边界（主接缝）**。测试 spawn `node xq.cjs ...`，断言 stdout 与对局文件。走的是外部行为而非实现细节，覆盖「开局 → 走子 → 将军 → 将死 → 悔棋」整条链路，也顺带锁住命令面与退出码的契约。绝大多数场景应该在这里测。
2. **规则引擎纯函数（次接缝）**。只用来测着法生成的逐子表格：各子力在若干给定局面下的合法着法集合，含蹩马腿、塞象眼、炮翻山、兵过河、将帅照面这些边界。理由是用 CLI 逐例跑又慢又吵，而这类表驱动断言正是纯函数最擅长的。记谱互转同样在这个接缝上做往返测试。

网页一条 Playwright 行为测试：写一份派生视图、打开页面、断言棋子位置与提示随之更新；再把派生视图删掉，断言页面降级回本地自由摆棋。浏览器测法已有先例可循——`_probe/` 里的脚本就是这套跑法。

## Out of Scope

棋钟与计时、多局管理与存档回放、残局库、AI 难度分级、挂 UCI 引擎当对手、联机与观战、手机端专门适配、悔棋到任意一手、把页面写回 CLI 的各种变通（下载目录监听、剪贴板桥等）、长将判负、以及**任何需要起本地 http 服务才能做的事**。

## Further Notes

- `_probe/` 是 ADR-0001 的原始证据，不是待清理的垃圾，别删。
- `state/` 是派生目录，不入版本库。
- 这一期最容易被低估的活是中文记谱的双向转换，尤其是同列重子的「前/中/后」；它比规则引擎更容易出现难查的边界错误。
